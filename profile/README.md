# PL/SQL Developer - Package workspace for Oracle you own

Packages and the SQL window should stay on an Oracle instance you own. Loose files wait off the live workspace.

## Session Card

| Slice | What you do in PL/SQL Developer | What remains |
|-------|---------------------------------|--------------|
| Arrival | Open PL/SQL Developer on an instance you own and name the Oracle desk | A titled code session |
| Focus | Keep the package editor on one unit you own | A short unit list |
| Check | Read the package before you compile units you own | A confirmed SQL window |
| Handoff | Leave the PL/SQL Developer Oracle desk on that instance | A note for the next visit |

## How PL/SQL Developer Sits

PL/SQL Developer does not replace the Oracle instance you already run. It sits beside that engine as a named package editor and SQL window for a PL/SQL Developer Oracle desk you own.

A first visit should be one short unit, then the same PL/SQL Developer code session the next day. That is enough to see if the layout holds on packages you own.

## Traffic Light

| Signal | On the PL/SQL Developer Oracle desk | What you do |
|--------|-------------------------------------|-------------|
| Green | Named instance, package beside the SQL window | Continue the same code session |
| Amber | Units from two schemas mixed | Split the set before a large change |
| Red | No title, loose files everywhere | Stop and name the Oracle desk first |
| Clear | Handoff written, unit list short | Close PL/SQL Developer and leave the desk |

## Open Order

1. Open the last PL/SQL Developer session on an instance you own, not a new empty workspace.
2. Read the package editor and the last SQL window.
3. Finish one visible unit inside PL/SQL Developer package editor.
4. Write what changed on packages you own, then close with fewer loose files than you found.
5. If the Oracle desk feels crowded, drop anything that belongs to a different schema.

## After a Week

A week in PL/SQL Developer is not a longer unit pile. It is the same package editor, a shorter SQL window list, and a note that still makes sense on Monday.

Other programs stay where they are. PL/SQL Developer only keeps the path back: instance name, packages, SQL window, handoff.

## Sign-off

- [ ] The PL/SQL Developer workspace name is short enough to scan
- [ ] Only packages you own are in the editor
- [ ] A second person can read the last unit
- [ ] The last PL/SQL Developer session still opens after a restart
- [ ] Finished units are off the live set
- [ ] The SQL window still matches the PL/SQL Developer Oracle desk

## Field Note

PL/SQL Developer is easier to trust when the package editor stays smaller than the script folder around it. Name the instance, keep units you own, finish one visible compile, and write what changed.
